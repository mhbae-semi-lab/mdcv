# 유지보수·업데이트 계획

| 항목 | 주기 | 내용 |
|---|---|---|
| 분류 사전(설비명·키워드) | 월 1회 | `packages/shared/rules.json` 하나만 고친다(Python·TS 공용). `node --test "tests/js/*.test.ts"`, `python scripts/parity.py`, `python scripts/evaluate_fab.py` 재실행 |
| 골든 데이터셋 | 분기 1회 | 익명화된 실메일 20건 이상 추가, 정확도 하락 시 가중치 조정 |
| LLM 프롬프트 | 변경 시 | `mdcv/llm.py`의 `PROMPT_VERSION`을 올리고 변경 사유를 이 문서에 기록 |
| 의존성·보안 패치 | 월 1회 | `npm audit`, `pip` 업데이트, GitHub Actions 결과 확인 |
| 버전 관리 | 릴리스마다 | 시맨틱 버전(v0.1.0…), 변경 로그를 GitHub Releases에 기록 |
| 백업·복구 | 일 1회 백업 | `python scripts/backup.py` (최근 14개 보관, 키 파일 포함), 분기 1회 복구 리허설 |
| 모니터링 | 상시 | API `/health`, 서버 로그(요청·동기화 실패), 알림 실패 로그(`notification_logs`) 주간 점검. 계정 동기화가 실패하면 화면 왼쪽 계정 줄과 설정에 사유가 표시됩니다 |

## 업데이트 절차
1. 기능 브랜치에서 개발 → 테스트(`python scripts/evaluate.py`, 웹 `next build`) 통과
2. `docs/test-results.json` 갱신을 확인하고 검수 후 main 병합
3. Docker 이미지를 새 버전 태그로 빌드·배포, 이상 시 이전 태그로 롤백

## 프롬프트 변경 이력
- classify-v1 (2026-10-23): 최초 분류·요약 프롬프트
- classify-v2 (2026-11-22): 반도체 설비 현장 기준 중요도 정의, JSON 스키마 강제, 답은 `validate_answer`(본문에 없는 설비·기한 거부, 점수-등급 일치) 통과 시에만 사용

## 운영 메모
- **자동 동기화**: 연동한 계정은 서버가 `MDCV_SYNC_MINUTES`(기본 10분)마다 최신 메일을 가져옵니다. 첫 동기화는 최근 100건을 받고 알림은 보내지 않습니다(과거 메일 알림 폭주 방지).
- **알림**: 새로 들어온 긴급·중요 메일만, 메일당 한 번 알립니다. 사용자가 중요도를 직접 바꾼 메일은 재분류·재동기화해도 유지됩니다.
- **복구**: 백업 `.db` 파일을 `MDCV_DB` 위치에 복사하고, 같은 이름의 `.key` 파일을 `mdcv.key`로 복사(또는 `MDCV_SECRET` 동일하게 설정)한 뒤 서버를 시작합니다. DB 구조는 시작할 때 자동으로 최신으로 올라갑니다.
- **로그**: 표준 출력으로 `시각 레벨 모듈 메시지` 형식. `MDCV_LOG_LEVEL=DEBUG`로 상세 확인.
- **제한**: 메일 본문 첨부파일은 처리하지 않습니다. 사용자별 계정 분리는 아직 없습니다.
- **암호화**: 토큰과 메일 본문은 AES-256-GCM(`v3:`)으로 저장합니다. 이전 형식(v1·v2)과 평문 본문은 서버 시작 때 한 번 다시 암호화되고 `audit_logs`에 `migrate_encryption`이 남습니다.
